## 1. 模板系统

Template 页面位于 `features/template`，负责边框水印的完整生产流程：模板渲染、属性编辑、图片资产管理与批量导出。通用工作台布局组件位于 `shared/layouts`，经 `panels` 插槽接入。

### 1.1 模板运行系统

独立的模板运行系统负责执行 React 模板，职责：注册模板、加载元信息、解释 `propsSchema`、将 props 转化为可编辑 UI、管理生命周期、为导出提供稳定渲染目标。

```txt
Template Selector → Template Registry → propsSchema → Template Runtime → DOM → Export Pipeline
```

### 1.2 Template Selector

- 单行下拉选择器，只占一行高度，展开后展示当前内置模板：`Minimal` / `Film` / `白框` / `圆角` / `叠字` / `平铺水印`
- 收藏的模板在下拉里置顶，当前模板可一键收藏或取消收藏
- 最近切换过的模板排在未使用过的模板之前
- 下拉支持键入首字母跳转，不单独占用搜索框

### 1.3 Template Props

属性表单必须由 `propsSchema` 自动生成，禁止手写模板专用表单；schema 同时定义默认值、类型、控件形态与校验规则。注入给模板的图片地址与 EXIF 数据不属于参数，不进入 schema。

典型参数：边框宽度、字体、字体大小、颜色、圆角、Logo。字段结构见 [architecture.md](./architecture.md) §5.2。

### 1.4 尺寸口径

模板几何一律表达为渲染基准 `--co-base` 的倍数，数值参数的取值是「相对画布宽度的比例」。

从旧版模板迁移时按统一系数换算：旧运行时会把主图覆盖成 `4·aspect rem × 4rem`（主图高度恒为 `4rem`，3:2 时宽度为 `6rem`），折算到「主图占 0.9 画布宽度」后得出：

```txt
1 旧 rem ≈ 0.15 画布宽度比例
```

所有模板共用该系数，避免同一家族的字号、圆角、阴影出现量级差异：

- 旧版中本就是百分比语义的参数（如九宫格偏移）不受该系数影响，直接沿用百分数
- 旧版以画布高度为基准的值，需按目标宽高比另行换算

### 1.5 背景

背景是框架级能力，与模板自身的参数体系相互独立：模板有没有自己的边框，都不影响它。模式为 `无背景 / 纯色背景 / 照片模糊`，默认照片模糊，字段含义见 [architecture.md](./architecture.md) §5.3。

- 默认值由当前模板提供，用户可覆盖；切换模板时背景重置为该模板的默认值
- 字段按模式条件显示，不相关的字段不出现在面板上
- 内边距与模糊强度都是相对画框宽度的比例，不是像素值
- 有背景时可调**画框比例**：默认 `自动` 跟随照片比例（横竖由照片决定），可手动选固定比例（`1:1 / 3:2 / 2:3 / 4:3 / 3:4 / 16:9 / 9:16 / 16:10 / 10:16`），竖照片也可选横向让模糊背景横排；它统一决定预览「适应」档与导出的目标框比例，见 §3.5
- 背景是否启用会改变导出尺寸的语义，见 §3.5
- 背景属于单张照片，可单独一键应用到其余照片
- 纯色模式下提供从当前照片提取的**主题色盘**（前 5 色，按占比从高到低排列）：点击色块即写入背景颜色，当前颜色对应的色块带勾选标记
- 首次在某张照片上使用纯色背景时，颜色仍为默认值则默认取第一个主题色；用户改过颜色后不再覆盖
- 主题色按图片缓存为派生数据，不写入配置；提取失败时只保留手动取色

## 2. 拼图系统

Collage 页面位于 `features/collage`，与 Template 完全独立：不共享编辑器、不共享布局逻辑、不共享页面状态，仅复用 Export Pipeline 与 Asset Infrastructure（含全局文件来源与素材会话）。

### 2.1 数据流

```txt
全局文件来源（内容面板，文件夹直览）
↓
Layout Mode / Preset
↓
Collage Canvas → DOM → Export Pipeline
```

### 2.2 Grid Layout

- 适合规则拼图，由布局预设驱动，优先支持固定格数与自动布局
- **画布比例（Grid / Free / 自适应共用）**：属性面板提供 6 种预设 + `自定义`宽:高数字输入（单侧 1~999，比例整体钳制 1:5 ~ 5:1）；画布**四边中点为 T 字形把手（横梁压在画布边缘线上、竖茎伸向画布内侧）、四角为 L 形（横竖两臂贴角）把手**（hover 浮现，`nwse/nesw/ew/ns-resize` 光标），拖拽调出自由比例，整段拖动合并为一步撤销。拖拽采用**对边锚定**：对侧边在屏幕上定住、只有被拖的边向外延伸，画面不居中重排；自适应的套内容框贴住锚定侧，余量（留白）只向拖拽方向堆积。画布不被视口钳制——拖到预览区边缘时**保证被拖边持续可见**：向下/右拖 → 预览自动滚动跟随（拖拽边钉在预览边缘、锚定边随滚动滑出）；向上/左拖 → 滚动原点不能为负，改为被拖边钉在预览边缘、原锚边延展（视觉与滚动等价，盒内无负坐标）。画布可以一直拉长；松手后可滚回查看全貌。拖完保持手动几何不回弹；点预设 / 撤销改比例 / 视口尺寸变化时回归自适应视口居中。预览默认自适应视口大小，比例只决定长宽形状，具体输出像素仍由导出配置决定
- **照片填充（画布级，Grid / Free / 自适应共用）**：`裁切填满`（cover，默认）铺满格子、超出部分裁掉；`完整显示`（contain）照片完整入格、留白透出画布背景（背景色 / 照片模糊），已有照片的格子不再垫占位底色。自适应在自动比例下格子与照片同比例、两种模式渲染一致，拖过分割线后由该设置决定超出部分；导出截取同一 DOM，预览与导出自动一致

### 2.3 Free Layout

- 适合自由摆放，支持位置与缩放调整；单图属性由 Selection 面板控制
- 层叠顺序即画布添加顺序，暂不提供手动排序

### 2.4 Adaptive Layout（自适应）

- 按拖放方位动态生成布局：新照片拖到目标照片的哪一侧，目标矩形就一分为二（左右 → 两列，上下 → 两行；递归进行，例如下半区再左右分即「上一下二」）
- 数据结构为二叉分割树（`adaptiveTree`，leaf = 一张照片，split = 按 `h`/`v` 二分），随 undo/redo 与持久化走；移除照片时父节点自动塌缩为兄弟
- **所有照片保持原始宽高比**：左右分两子树等高、宽度按比例分配，上下分两子树等宽、高度按 `1/比例` 分配；自动比例下每个格子的比例 == 照片比例，无缝填满、零裁切零变形（手动拖过分割线后由「照片填充」决定超出部分）
- **分割线可调**：每个分割节点的接缝上有把手（hover 显示细线，`col/row-resize` 光标），拖动即写入手动比例（children[0] 占分割轴的份额，钳制 5%~95%），双击恢复按照片比例自动推导；手动比例随树持久化，整段拖动合并为一步撤销
- **格内取景可调**：单击照片选中（描边高亮），画布上直接拖动平移、属性面板「选中项」调缩放（1~3x）与水平 / 垂直位置，双击照片重置；位移按**格子尺寸的比例**存储（随格子缩放同比例保持，视口变化不漂移），钳制在「照片边缘贴住格子边」的可达范围内——裁切填满不露背景缝、完整显示不把照片拖出格子，恰好铺满时需先放大才可平移；取景随树持久化、进撤销历史（拖动合并一步），换图 / 替换照片时重置，导出截取同一 DOM，预览与导出一致
- **画布比例（套内容）**：默认「跟随内容」——画布 = 根节点自然比例、照片树整框铺满；属性面板可切固定比例（`1:1` / `16:9` / 自定义宽:高）或直接拖画布边角把手接管为自由比例——画布按所选比例呈现，照片树按自然比例 contain 进画布内容框（缺省居中；拖把手时贴住锚定侧，余量向拖拽方向堆积，见 §2.2），余量透出画布背景（背景色 / 照片模糊 / 图片），照片始终零裁切；边距、圆角、阴影照常作用于画布外框，导出与预览一致
- **间距与边距相互独立**：间距只作用于照片之间（贴画布外沿的边不参与内缩），边距只控制外圈留白、可调至 0
- 交互：贴边（30% 带）高亮插入方位，中央区域高亮替换，空画布拖入即第一张；hover 照片浮现「移除」（只出画布，不删除文件）
- **落点细分与整体插入**：拖到照片上的落点一律细分或替换这张照片，不因其贴合画布外沿而升级（如上1下1 的下排占满整宽，拖到它左侧即分成上1下2）；拖到照片与画布边距之间的外框区域 → 沿该侧在根节点一分为二，新照片独占一整行 / 一整列（如在底部追加第三行）
- 导入 / 点击预览栏**不自动放置**，一律手动拖入；同图在画布中只保留一份
- 照片原始宽高由导入元数据提供（`CachedImageMeta.width/height`，含 HEIC ispe 解析），解析失败按 3:2 兜底

### 2.5 编辑历史（撤销 / 重做）

- 画布状态（布局与画布属性、间距 / 边距、槽位调整、自适应树改动、标注增删改）统一进撤销历史，最多 60 步，不跨会话持久化
- 连续拖拽合并为一步：拖拽期间只更新画布、不进历史，松手时才把拖拽起点入栈；原地未动或拖回原位不产生记录，因此撤销是「回到拖拽前」而不是按像素逐步回退
- 快捷键：`Cmd/Ctrl+Z` 撤销，`Cmd/Ctrl+Shift+Z`（Windows `Ctrl+Y`）重做；随拼图页挂载 / 卸载，其他页面不拦截
- 焦点在输入控件（输入框 / 文本域 / `contenteditable`）时不拦截，交还原生文本撤销

### 2.6 文字标注

- 工具栏「添加文字」在画布中心生成一条 `text` 标注；画布直接渲染文字层，hover 浮现描边，画布上拖动调整位置（整段拖动合并为一步撤销）；描边等编辑态装饰不进导出成片（`data-co-editing-chrome` 排除）
- 调整区「文字」区块（选中文字标注时出现），包含：
  - **文案**：多行输入；聚焦开历史基线、整段失焦收拢为一步撤销（逐键提交会把撤销退化成按字符撤销）
  - **排列**：横排 / 竖排切换（`writing-mode: vertical-rl`）；旧持久化数据缺该字段按横排兜底
  - **字体**：系统字体列表（`platform.storage.listSystemFonts()`，模块级缓存 + 并发去重），「默认字体」不写入 `fontFamily`、沿用应用默认字体栈；下拉悬浮 / 键盘高亮即在画布预览该字体，离开选项区、提交选中、下拉关闭、编辑器卸载均还原 —— 预览只改视觉，不写标注数据、不入历史、不持久化，且挂在独立 store 上（主 store 整店订阅的面板不随之重渲染，避免 Radix 下拉重定位打断滚动）
  - **字号**：8~96px，按画布渲染尺寸计、导出等比放大；**颜色**：取色器 + 色值文本；**旋转**：-180°~180°；**宽度 / 高度**：画布占比（5%~100% / 4%~100%），加宽 / 加高时同步回收越出画布的左缘 / 上缘；**删除文字**
- 快捷键：`Delete` 删除选中标注，`Esc` 取消选中；随拼图页挂载 / 卸载，焦点在输入控件时不拦截
- 文字标注随拼图状态持久化、进撤销历史；导出截取同一 DOM，预览与导出一致
- 本期只做 `text` 类型；`arrow` / `rect` / `circle` 类型与 store 已就绪，暂无 UI 入口（见 [TODO.md](./TODO.md) §2）

## 3. 导出系统

导出系统是 Template 与 Collage 共用的基础设施，不属于任何单个 feature；渲染结果的编码与保存通过 Platform Contract 完成，由 Rust 宿主执行。

### 3.1 设计目标

- 保证预览与导出结果一致；导出与预览共用同一套渲染组件（`TemplateBackgroundFrame` + `TemplateRuntime`）与同一套尺寸解算，导出在**离屏渲染节点**上进行，不改写预览区 DOM，也不维护与预览分离的第二套导出模板
- 导出在后台进行：进度 / 取消由全局任务状态驱动，导出期间用户可继续浏览与编辑，导出按启动时的配置快照渲染
- 支持 Template 与 Collage 两类来源、单张与批量导出、稳定的进度 / 取消 / 错误反馈
- 输出参数全部收敛进**导出预设**：一份预设描述完整的输出意图（存储、格式、尺寸、元数据），两页共用一份并持久化
- 导出直接写入目标目录；导出尺寸由预设的尺寸意图与画布几何解算，不随窗口大小或设备像素比漂移

### 3.2 基础链路

```txt
React → DOM → 预设尺寸解算（页面侧适配器） → 渲染基准解算 → snapDOM
      → Platform Export Service（encode PNG / JPG + 冲突命名 + save to directory）
```

- 渲染稳定性由 `core/renderer` 负责，导出任务调度由 `core/scheduler` 负责
- 抓图前导出服务调用页面提供的**尺寸适配器**：适配器就地解算预设的尺寸意图、应用渲染基准、返回实际命中的目标框，该目标框用于自动命名；离屏导出节点与预览根节点都由 Template 页面持有（`ExportRenderNode`）

### 3.3 导出预设与管线档位

分两层：

**导出预设（`ExportPresetProfile`，用户可见、持久化）**——`shared/types/export.ts` 定义，`useExportPresetStore`（`copicseal-export-presets`）持久化，两页共用一份，首启种子「默认预设」：

| 字段组 | 字段 | 说明 |
|------|------|------|
| 存储选项 | `destination` | `app-dir`（设置的导出目录）/ `source-dir`（原图所在目录，无原图时回落）/ `custom`（`customPath`） |
| | `subfolder` | 存储到指定名称的子文件夹；落盘时 Rust `create_dir_all` 顺带创建 |
| | `conflict` | `unique-name`（批内去重 + 磁盘已存在则追加序号）/ `overwrite` |
| 图像格式 | `format` / `quality` | `PNG` / `JPG`；品质仅 JPG 生效 |
| 图像调整尺寸 | `sizing` | `{ mode: 'auto' }` / `{ mode: 'scale', percent, noUpscale }` / `{ mode: 'fit', axis, px, noUpscale }`；`auto` 为以原图为基准的自动尺寸，`noUpscale` 为画质优先开关（不放大，见 3.4 / 3.8） |
| 元数据 | `includeExif` / `stripGps` | 保留 EXIF；进一步剥离 GPS（仅 JPG，见 §4.4） |

**管线档位（`ExportPreset`，平台接口的内部结构）**——描述一次抓图的编码参数（`format` / `width` / `height` / `scale` / `quality`），由页面从预设派生后传入 `exportSingle`：

- Template：`width/height` 占位为 0、`scale` 恒为 1——真实目标框由尺寸适配器解算，命名用其返回值
- Collage：`width/height` 为解算后的输出宽高（仅用于命名），`scale` 由预设尺寸意图折算成 snapdom 倍率
- 目标尺寸缺值或非正数时不允许导出；扩展名始终由 `format` 决定

#### 已知限制：暂不支持 WebP

macOS 端渲染在 WKWebView 里，它不支持用 canvas 编码 WebP：请求 `image/webp` 时 `toBlob` 会静默退回 PNG，产出的是一个后缀为 `.webp`、内容却是 PNG 的文件（体积与 PNG 相同，质量参数完全无效）。Windows 端的 WebView2 支持该编码，但当前按统一行为处理。

因此在 WebP 编码挪到宿主侧（Rust 侧 `image` crate 已支持有损 WebP）之前，`format` 只开放 PNG 与 JPG；扩展名映射同时做了运行期收敛，避免持久化的历史配置再产出后缀与内容不符的文件。

### 3.4 渲染基准与尺寸解算

模板的几何必须全部表达为渲染基准的倍数。基准以 CSS 变量 `--co-base` 提供，其值即**画布宽度**：

```css
padding: calc(var(--co-base) * 0.05);
font-size: calc(var(--co-base) * 0.022);
```

约束：

- 模板内禁止出现 `px`、`rem`、`vh`、`vw` 等绝对单位与视口单位；允许 `em`、`%` 与无单位比值
- 模板参数的数值字段是无单位比例，不是像素值
- 不得通过 `html { font-size }` 或全局 `rem` 实现缩放

导出时先由尺寸适配器解算预设的「图像调整尺寸」，再按目标框反解基准，使画布在目标分辨率下**真实重排**，而不是把小尺寸结果放大：

```txt
以探针基准渲染 → 测量画布与照片布局尺寸 → 按预设意图解算出目标框（resolveExportSizeTarget）
               → 按 contain 反解出命中目标框的基准 → 应用基准并等待渲染稳定 → 捕获
```

尺寸意图的解算规则（`resolveExportSizeTarget`，`features/template/lib/render-size.ts`）：

- `auto`（自动，以原图为基准）：无需填数值——模板页等价于 `scale` 100%（照片 1:1）并恒经 `shrinkTargetToPhotoNatural` 收敛；拼图页直接取画布位图源像素上限（见 3.8）
- `scale`（缩放图像）：按照片原始像素的百分比反解目标框，与预览的「缩放档位」同源（`100%` 即 1:1）
- `fit`（调整大小至）：按画布比例给目标框，主导轴（长边 / 短边 / 宽度 / 高度）精确命中给定像素
- `noUpscale`（画质优先，两种模式都生效）：目标框超出照片原始像素时整体缩到不越过原图（`shrinkTargetToPhotoNatural`），绝不插值放大；照片未加载时保持原目标框，不阻断导出
- 探针测量会写入临时基准，因此解算与 `applyRenderSize` 必须在同一任务里连续执行，中间不得有 `await`；两者作用于离屏导出节点，即使基准被看到也只落在视口外、不会闪进预览区。量不出目标框（照片未加载）时抛错，该张跳过

因为 `--co-base` 就是画布宽度，内容高宽比与基准无关，一次测量即可线性反解：

```txt
base = min(目标宽, 目标高 / 内容高宽比)
```

主导轴精确命中设定值，另一轴按比例推导，不补边、不变形。测量必须使用布局尺寸（`offsetWidth` / `offsetHeight`），不得使用受变换影响的边界矩形。

### 3.5 背景与尺寸

渲染区由**画框**与**画布**两层组成：画框在最外层，承担背景填充与内边距；画布是模板本身，几何全部是 `--co-base` 的倍数。背景模式直接决定目标框的角色：

| 背景 | 画框 | 画布 | 1280×720 + 方形画布的结果 |
|------|------|------|---------------------------|
| 无背景 | 贴合画布 | 按 contain 命中目标框 | **720×720**（宽度按内容比例重算） |
| 纯色 / 照片模糊 | **精确等于目标框** | 在扣除内边距后的内容盒内 contain | **1280×720**（模板内嵌，其余由背景填充） |

- 内边距与模糊半径都写成画框宽度 `--co-frame` 的比例；竖直内边距同样以画框宽度为基准，因此不依赖画框高度
- 模糊背景的外扩量取模糊半径的两倍，避免模糊之后画框边缘透出
- 画框属于框架层，其像素尺寸由解算逻辑直接设置，不受「模板内禁止绝对单位」的约束
- 导出尺寸解算只写离屏导出节点，预览自适应与它互不干扰，无需挂起自适应

#### 预览与导出的目标框

解算规则只有一套，预览与导出的区别只在于**目标框是谁**：

| 场景 | 目标框 |
|------|--------|
| 导出 · scale | 让照片宽度命中「原始像素宽度 × 百分比」所需的目标框；有背景时画框按画框比例（覆盖值或自动反推）取包住画布与内边距的最小框 |
| 导出 · auto | 同「导出 · scale」的 100%（照片 1:1），并恒收敛到不越过照片原始像素 |
| 导出 · fit | 画框比例的手动覆盖值优先，否则按画布（照片）比例；主导轴命中给定像素的目标框 |
| 预览 · 适应 | 按画框比例（手动覆盖值，否则照片比例）contain 进预览可用区，四周留白 |
| 预览 · 缩放档位 | 与导出 · scale 同源（`100%` 即 1:1），因此同样遵循画框比例覆盖值 |

由此产生两条结论：

- 无背景时导出尺寸由画布比例决定，有背景时精确等于解算出的目标框尺寸
- 预览与导出的**比例来源相同**：画框比例的覆盖值，否则照片比例，预览只是把它 contain 进可用区——预览与导出形状一致，letterbox 留白即预览区与目标框的差。唯一例外是 scale 导出的自动画框比例含内边距展开（与照片比例相差约几个百分点），预览按照片比例呈现

### 3.6 倍率与像素比

- 输出倍率只由预设的尺寸意图折算而来，在解算尺寸之上做位图超采样：
  - Template 走渲染基准反解，管线倍率恒为 `1`
  - Collage 折算成 snapdom `scale`（可小于 1，用于「调整大小至」比画布渲染尺寸更小的场景；内部预热已验证 <1 可用）；`auto` 直接取源像素上限、`noUpscale` 以画布位图源像素收敛倍率（均见 3.8）
- 光栅化像素比固定为 `1`，避免设备像素比隐式放大结果
- 导出分辨率元数据（`dpi`）只写入 EXIF，不参与尺寸计算（写入尚未实现，见 TODO）

### 3.7 Template 导出

- 拖照片到预设行导出单张、行内主按钮导出当前照片、行内「导出全部照片」按素材会话顺序逐张导出；全部使用**同一个预设**，逐张按各自的模板、参数与背景渲染
- 模板配置属于图片本身（§1），预设属于全局：批量导出不是把一套样式复制多份，而是逐张按自身配置渲染 + 按共享预设落盘
- **离屏后台导出**：导出渲染在视口外的 `ExportRenderNode` 上进行，与预览共用同一套渲染组件与尺寸解算；预览区 DOM 全程不被改写，导出期间用户可继续浏览、切换照片与调整参数
- **配置快照**：`beginRun` 时对每张照片 `structuredClone` 一份 `{templateId, params, background}`，导出严格按启动那一刻的配置渲染，导出期间的编辑不回溯到本批任务
- **就绪判定**：离屏节点带 `data-co-export-job` 标记，逐任务轮询等待新布局提交（超时按单张失败跳过），再等图片加载与 DOM 稳定，避免量到上一任务残留的旧尺寸
- 导出节点以 `visibility: visible` 覆盖隐藏页的 `invisible`，因此用户切到其它页面后导出仍继续
- 拖入的照片若尚未入会话，先按路径懒导入，导入完成（会话列表更新）后由 effect 接手导出
- 单张失败（尺寸量不出、写盘失败）只跳过该张，结束后汇总提示跳过数量
- 导出前必须确保离屏节点内的图片已加载完成、EXIF 已就绪，否则会按占位比例或空元数据渲染，导致尺寸偏差或水印缺项

### 3.8 Collage 导出

- 拖照片到预设行、行内主按钮一律导出当前画布（拖拽只是触发器）；不提供批量
- Collage 不参与模板的基准解算：`resolveCollageSizing`（`features/collage/export-size.ts`）按画布渲染尺寸与预设意图折算 snapdom 倍率，输出宽高（`画布 × 倍率`）仅用于自动命名
- **画质优先（`noUpscale`）**：以画布位图的源像素为上限收敛倍率——逐张量出照片（`<img>` 的 object-fit 盈缩 × transform 取景缩放 1~3x，含画布背景照片）的 1:1 倍率取最小，需求像素最多的大槽位照片原样输出、其余全部真实缩小，绝不插值放大；边框 / 间隙 / 文字标注是 CSS 绘制、随倍率重新光栅化，不参与约束。量不出任何照片（空画布 / 未加载）时回落「不放大到画布渲染像素之上」的历史口径
- **自动（`mode: 'auto'`，以原图为基准）**：直接把上述上限作为倍率——预设不再填数值，输出尺寸完全由画布位图决定（最紧一张 1:1、其余缩小）；量不出照片时按画布渲染尺寸导出。与 `noUpscale` 的区别：`auto` 没有预设数值这层上限，`scale` / `fit` + `noUpscale` 则取「预设值与源像素上限的较小者」
- 快照内联降采样（`capEmbeddedImages`）与上述口径对齐：降采样目标 = 实际绘制尺寸 × 倍率（object-fit 盈缩与取景缩放都折进来），保证栅格刚好够用且不过大
- 拼图没有单一原图：`source-dir` 去向回落到设置的导出目录，且不搬运 EXIF（`preserveExif: false`）

### 3.9 导出任务状态

至少包括：所属预设、已完成数量 / 总数量、取消状态、错误信息。

进行中的任务状态收敛在**全局 store**（`useExportRunStore`），同时显示在两处：

- **顶栏进度胶囊**（`CoExportProgressPill`，视图菜单左侧）：细进度条 +「已完成 / 总数」+ 取消按钮，任何页面可见，导出转后台、用户切页时进度不丢；空闲时不渲染
- **所属预设行内**：转圈 +「已导出 N / M」，总数大于 1 时追加「取消」按钮

`runScheduledExports(onProgress)` 推进进度、`onTaskCreated` 回填 `taskId` 后由 `cancelExportTask` 置取消位；取消在两张照片之间生效，当前这张仍会导出完成，并提示「已取消批量导出」。全局同时只跑一个导出（两页共用同一份任务状态），进行中时预设的新增 / 编辑 / 复制 / 删除与全部导出入口禁用。结束后的完成通知与错误提示由统一通知承载；任务来源、当前文件名与逐张档位级的进度明细暂不展示。

### 3.10 命名、目录与冲突

- 目录由预设的存储选项解析（`resolveProfileOutputDir`）：`app-dir` 取设置 → 导出里的「文件导出目录」（`output.default_path`）、`source-dir` 取原图所在目录、`custom` 取预设自带目录；再拼上子文件夹（单段目录名，分隔符与非法字符替换为 `-`）。读不到可用目录时退回逐次保存对话框兜底
- Template 自动命名：`{原始文件名}@{宽}x{高}.{格式}`，宽高取尺寸适配器实际命中的目标框（取整）；Collage 自动命名：`拼图@{宽}x{高}.{格式}`
- 扩展名始终跟随 `format`；非法字符会被替换
- 冲突策略（预设 `conflict`）：
  - `unique-name`（缺省）：先在批内去重，再查磁盘（`path_exists`），已存在则追加 `-2`、`-3` 序号
  - `overwrite`：直接用原名覆盖

### 4.4 输出策略

导出时是否保留元数据由**导出预设**决定（没有全局开关）：

- `includeExif` 开启且格式为 JPEG 时，把原图的 EXIF 段原样拼回输出（相机参数、拍摄时间、镜头、光圈快门 ISO 等）；PNG 没有 EXIF 段，此开关对 PNG 无效果
- `stripGps` 在保留 EXIF 的基础上进一步剥离位置信息：Rust 侧 `strip_exif_gps` 删除 IFD0 中的 GPSInfo 指针（`0x8825`）条目——只改条目表与 APP1 段长度，数据区偏移不动，其余字段仍然可读；结构异常时原样返回，绝不把可读的 EXIF 改坏
- EXIF 提取 / 拼接 / 剥离失败不阻断导出（`console.warn` 后按无该部分元数据输出）
- 导出分辨率（DPI）写入尚未实现，见 [TODO.md](./TODO.md)
